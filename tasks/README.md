# Scheduled task definitions

This directory versions reusable prompts for the optional desktop tasks, grouped by runner: `tasks/claude/` holds the six trading-task prompts, the macro-lens publisher and the independent daily valuation job written for a Claude Desktop local task, and `tasks/codex/` holds runner specifications for Codex (a Codex variant of the daily valuation job). Copy or register them in your own task runner; the repository does not assume a specific user profile or local task registry.

| Task | Calendar gate (`agent_jobs.py due --kind`) | Purpose |
|---|---|---|
| `heartbeat` | `heartbeat`: any exchange session day; non-session days skip | Refresh broker state, reconcile fills and emit risk/exit alerts. |
| `overnight-briefing` | `briefing`: before the session opens | Build a portfolio and entry-plan briefing with the technical research receipt, the code-rendered risk receipt and the macro-lens lines (`--brief`) as `[FYI]`. |
| `postclose-transition` | `postclose`: 10 to 60 minutes after the actual close | Evaluate exits, apply close-confirmed transitions, render their transition receipts, run technical research with the code-rendered risk receipt and process controlled repaints. |
| `gate-ladder-report` | `ladder`: 20 to 60 minutes after the close, then wait for the same-session post-close receipt | Render the current gate ladder. |
| `macro-lens` | `macro`: 30 to 60 minutes after the close; does not wait for the post-close receipt | Refresh the cross-asset daily series and publish the code-rendered macro lens (`quant/journal/macro_lens_log.py --update --session <session>`: reading, ledger, full text) as its own message. If the session's bars are not all in, it writes nothing and exits with code 3. No model call, no authorization. |
| `chart-read` | `chart`: 35 to 60 minutes after the close, then wait for the post-close receipt | Render the list of the two tradable setups (bottom, trend confirmation) that have formed or are forming, without a model call or authorization. |
| `weekly-portfolio-review` | `weekly`: calendar-independent | Audit exposure, process, data quality and rule adherence with technical and risk research (the only multi-role model workflow), the weekly macro-lens review (`--week`) and the agent-layer weekly baseline; valuation is not part of it. |

The independent daily valuation job is specified in `tasks/claude/valuation-daily.md` (Codex variant: `tasks/codex/valuation-daily.md`): it refreshes company and completed-bar caches, freezes inputs, runs the valuation chain (the risk-free rate comes from the cached 10-year daily series; no macro model stage) plus the unvalidated research-grade 12-month targets through `quant/ops/valuation_daily.py --run --json`, and archives its own receipt and report under `var/valuation-daily/`. Briefing and weekly review do not run the valuation CLI, the valuation role or the card mirror. It is a judgement layer with zero authorization effect and registers no schedule by itself.

Every prompt starts with `python3 quant/ops/agent_jobs.py due --kind <kind>`. The gate reads the pinned XNYS exchange calendar (`quant/core/market_sessions.py`): holidays, half days and daylight-saving changes are decided there, so the post-close prompts (offsets of 10 / 20 / 30 / 35 minutes for postclose / ladder / macro / chart) can be registered on several wake-up slots (for example ten minutes past each candidate closing hour) and only the slot inside the actual window runs. The calendar refuses to answer outside its supported range or without its dependency; a prompt must then report the error instead of falling back to a fixed clock time. The ladder and chart prompts additionally wait for the same-session post-close job to settle (`quant/ops/agent_dependency.py`), because the calendar decides when to start, not whether the upstream work finished. That wait takes no private timeout: its budget is the post-close job's own lease.

The daily loop runs only the technical model role (a run is reused for the same close and card revisions); risk receipts are rendered by `quant/report/risk_receipt.py`, and the technical + risk model workflow runs only in the weekly review. Macro is not a model role: the macro lens is rendered by code. When `agents/routing.json` sets `execution_transport` to `desktop`, the heartbeat, briefing, post-close and weekly prompts start their controller with `quant/ops/agent_desktop.py launch --kind <kind>` and the session serves its own runtime's research requests under `tasks/desktop-research.md` until the round's completion file appears. The chart and macro-lens tasks make no model call.

Cadence is configured in the operator's timezone. Prompts assume the repository is the task working directory, local state is configured, and any external notification credentials are present only in environment variables. Domain research and reviewed card updates belong to the controller described in `agents/README.md`; the prompts only quote its receipts, and only a `status == "applied"` receipt is a written card.
