# Weekly portfolio review

Review the locally configured portfolio without publishing account data.

Valuation refresh, calculation and reporting belong to the independent `valuation-daily` task (`tasks/claude/valuation-daily.md`); this review does not run the valuation CLI or the valuation role, and does not splice in a valuation section.

0. Run `python3 quant/ops/agent_jobs.py due --kind weekly` (calendar-independent; it only confirms the gate contract). Refresh data first, then run the technical and risk research, then assemble the report.
1. Run the portfolio brief with `--read-only` and run the performance report. Weekly review must not consume the shared alert cooldown used by scheduled heartbeat, briefing and post-close modes.
2. Take the weekly NAV change from `python3 quant/report/nav_report.py --days 7`. It nets out external cash flows from the ledger maintained by `quant/data/cash_flow_sync.py`; never subtract the first and last NAV rows yourself, because a deposit or withdrawal would be reported as performance. Quote its warning lines when the ledger does not cover the window.
3. Audit exposure, concentration, shock budget, at-risk limits, option DTE/IV, stale cards and unresolved infrastructure warnings. Take the stale-candidate list from the brief's `watchlist_stale` output rather than scanning the watchlist file, so cards removed from the broker-side candidate group are not reported as live candidates.
4. Reconcile broker quantity, lots, fills and journals before judging performance.
5. Separate process quality from outcome quality; identify rule-external actions that need annotation.
6. Run `python3 quant/ops/agent_jobs.py run --kind weekly --scheduled --json` (When `agents/routing.json` sets `execution_transport` to `desktop`, read `tasks/desktop-research.md` first and run `python3 quant/ops/agent_desktop.py launch --kind weekly` instead; serve this runtime's research requests until the round's completion file appears, then read the controller output file as the job receipt. The launch receipt itself is only a handle) and place the technical and risk conclusions and unknowns in their sections. Risk conclusions must cite the mechanical receipts of the same frozen snapshot. A missing or failed role is reported as missing, never filled in with a confident guess, and generating the report is not a verification pass. The weekly review is the only multi-role model workflow; the daily loop runs only the technical role with a code-rendered risk receipt. Macro is not a model role.
6b. 🌐 Macro weekly review: paste `python3 quant/journal/macro_lens_log.py --week` verbatim into its own section (it reads the ledger `trade/intelligence/macro/ledger.jsonl`: environment-band track, days per strongest driver, what the market was trading, reading flips, and a check of last week's strongest driver), with the latest `--digest` folded in a `<details>` block. It is zero-authority `[FYI]`: never recommend freezing or downgrading a plan from it and add no macro reasoning of your own.
7. Render the agent-layer baseline with `python3 quant/report/agent_metrics.py --days 7` and place both tables verbatim at the end of the report (rounds, calls, prompt bytes and token estimates, applied cards against targets, SLA, unknowns and failure classes). The numbers carry job ids and are not a judgement of research quality or returns.
8. Record reusable methodology only after removing identifiers and personal account values.
9. Do not place orders or push local state to a remote repository.
