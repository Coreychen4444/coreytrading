# Independent daily valuation (Claude runner)

Run only from the root of the private runtime checkout of this project. If the working directory does not match, return `PROJECT_ROOT_MISMATCH` and do not create substitute files in another repository.

Schedule: a runner-bound project task, daily at 08:00 in the operator's timezone, including weekends and market holidays. It refreshes company data and completed daily bars itself and does not wait for or call the pre-market briefing or the weekly review. The valuation role's route is set in `agents/routing.json`; a Codex-runner variant of this job is described in `tasks/codex/valuation-daily.md`, and only one of the two should be registered. Research judgements have zero authorization effect.

## Two outputs that never stand in for each other

- **Research-grade 12-month targets** (`quant/valuation/research_target.py`), computed automatically at the end of the daily run, written to `research_targets.json` and placed at the top of the report. Midpoint = the compact EPS package's base EPS × the ticker's current core PE (multiple unchanged); scenarios = downside / upside EPS × the current PE; multiple band = the ticker's 3-year PE p25–p75; a cash view (FCF yield, FCF ÷ net income) and the reverse-DCF implied growth (the 10-year annual earnings growth the current price requires) sit beside it. Quarters enter TTM on their earnings reaction day (the +45-day lag is only the fallback) and one-off non-operating items above 25% of revenue are stripped pretax. Names whose EPS cannot anchor the target (forward/trailing EPS ≤ 0, near-breakeven PE, no EPS package) take an EV/revenue route (next-year revenue × today's forward EV/revenue, less net debt rolled by TTM FCF) plus the year-5 revenue the current price implies at the archetype's steady-state margin (a lower bound). `semi_cyclical` names carry a cyclical flag with a cycle-average side reading; when forward EPS grows more than 50% the midpoint becomes √(constant multiple × cycle average) and an EPS-surge bias flag is attached — declared, unvalidated rules. **Unvalidated, not a fair value and not a probability interval**; every number is delivered with its flags as is.
- **Per-company accepted publication** (`publication.json` / `released_counts`): only outputs with `status=released` may be delivered on their own basis, and without real acceptance records the publishable count is 0. Research-grade numbers are never called "approved for publication".

## Steps

1. Read `AGENTS.md`, `quant/valuation/README.md`, this file and `tasks/desktop-research.md`.
2. Run `python3 quant/ops/agent_desktop.py launch --kind valuation` and note the controller id, output and completion paths. Without the desktop transport, run `python3 quant/ops/valuation_daily.py --run --json` instead. This single entry point owns the dynamic holdings ∪ candidates scope, refresh, freeze, the host calculation → valuation review chain, per-day deduplication and the independent report archive. Do not run pipeline or agent_jobs.
3. Claim this runtime's valuation requests under `tasks/desktop-research.md`, produce the contract JSON directly and submit it; loop until the completion file appears. Do not start another model CLI and do not launch twice.
4. Read the output: `busy` or `skipped/already_attempted_today` → report briefly and stop (never add `--retry` automatically); `failed` / `partial` → name the failing stage, refresh errors and the artifacts that do exist. Never edit code or data to get around a failure, and never present an old report as today's result.
5. On normal completion read the job receipt's `report` and `research_targets`. Optionally forward the phone layout of the research targets (midpoint vs price table / valuation position table / warnings / tickers without output, per-ticker EPS and basis folded) by piping it: `python3 quant/valuation/research_target.py --tg-latest | python3 quant/ops/tg_notify.py --stdin`. The message body is only the code-rendered output; add no prose and change no numbers.
6. **EPS package review.** The compact EPS package (`quant/valuation/eps_model.py`, `trade/valuation/eps_models.json`) is the research target's EPS source and rolls forward mechanically after each earnings report. For every ticker the report lists under "rolled mechanically after earnings (pending review)" or whose research line carries the unreviewed-roll flag, read the **issuer's primary disclosure** (the SEC filing or the company's own earnings release and guidance; no news media or social posts). If there is guidance, update it with `python3 quant/valuation/eps_model.py set --ticker T --quarter <ID> --revenue D B U --op-margin D B U` (quarter IDs from `eps_model.py show --ticker T`; downside / base / upside from the guidance range, margins from guidance or the latest quarter), then `eps_model.py review --ticker T --source <disclosure URL> --note "<one-line guidance>"`. Without guidance keep the mechanical roll and invent nothing. Cap each ticker at about fifteen minutes and carry unfinished tickers to the next day. Only the compact package is edited, never trading state.
7. Deliver in the session: valuation time, research-grade output count / total, the distribution of reasons for no output, changes against the previous research-grade result (compared only on the same basis; EPS, PE, price and stale inputs attributed separately; unknown when attribution is unclear) and the local report path.

Do not write trading state, zones, caps, broker orders or intelligence-workflow files, and do not commit or push.
