# Independent daily valuation task

Run only from the root of the private runtime checkout of this project. If the working directory does not match, return `PROJECT_ROOT_MISMATCH` and do not create substitute files in another repository.

This is the Codex-runner variant; the Claude-runner prompt is `tasks/claude/valuation-daily.md`. Register only one of them, matching the valuation role's route in `agents/routing.json`.

Schedule: a runner-bound project task, daily at 08:00 in the operator's timezone, including weekends and market holidays. The task refreshes company data and completed daily bars itself; it does not wait for the pre-market briefing or the weekly review and does not call them. The risk-free rate comes from the cached cross-asset daily series (`quant/data/macro_series.py`, refreshed after each session by the macro-lens task): the latest observation of the 10-year yield by observation time; older than seven days is reported as unknown (DCF paused, never fetched ad hoc). There is no macro model stage: the frozen macro-lens prior (environment band, strongest driver, reading) enters the valuation view as context only and never generates valuation scenarios. Macro news is never collected.

**Publication boundary.** The current valuation method has not passed acceptance and the host sets `publication.status = withheld`. The task keeps refreshing, freezing, archiving and checking gaps, but it must not present raw DCF values, same-path EPS/PE or their sensitivities as a usable fair value, twelve-month target or over/undervaluation verdict. Calculation success and method acceptance are reported separately: the delivery first states that the model awaits rebuild, valuations are not published and the publishable count is 0, and the numeric delivery items below are bound by this boundary. An older receipt without `publication` is not publishable either. The host has a per-company publication channel: only an exact output with `status=released` in `publication.json` may be delivered on its own basis, reporting the job's `released_counts`; it must bind this run's company inputs, the current code, a valid independent review and the acceptance evidence. Without real acceptance records the publishable count is 0, and trust or acceptance records must never be created to restore numbers. Historical reports are snapshots; check current validity read-only with `quant/ops/valuation_release.py status`. The unvalidated research-grade 12-month targets (`quant/valuation/research_target.py`) are a separate output and are never called approved. Tickers with a `company_models.json` research packet are captured through the same entry point and use the company engine; report `company_research`, the legacy `computed` count and the publishable count separately. An expired or unreconciled company packet never falls back to the legacy archetype; an earnings path may be explained as a clearly labelled research assumption, never as an approved market target. The daily report must classify each ticker separately: a dated conditional operating value, a long-run operating path that cannot be valued, stale inputs, and whether a per-share common-equity value or twelve-month target is approved for publication. A conditional operating value covers the operating business only and must never be relabelled as per-share fair value. A gap in one ticker must not block research output for the others.

1. Read `AGENTS.md`, `agents/README.md`, `quant/valuation/README.md` and this file in full.
2. Run `quant/ops/valuation_daily.py --run --json` with the project interpreter. This single entry point owns the dynamic holdings ∪ candidates scope, refresh, freeze, the calculation → valuation review chain, per-day deduplication and the independent report archive. Model routing and limits come from `agents/routing.json`. Do not start a separate valuation model and do not run pipeline or agent_jobs. When `agents/routing.json` uses the desktop transport, read `tasks/desktop-research.md` and start the same controller with `quant/ops/agent_desktop.py launch --kind valuation`: the Codex session claims its own requests (valuation only; the host calculation runs first) without starting a sub-model, and once the completion file appears it reads the output file as the business result described below.
3. `busy` means a run is already in progress: report briefly and stop. `skipped/already_attempted_today` means today was already attempted: do not add `--retry` automatically; read the returned existing record and report accurately whether it succeeded, partially completed or failed, then stop. `failed`/`partial` must name the failing stage, data-refresh errors and the artifacts that do exist. Never edit code or data to get around a failure, and never present an old report as today's result.
4. On normal completion read the returned `report`, `receipt` and `workflow` files and deliver the independent valuation report inside the runner session:
   - valuation/quote time, model version, coverage count, the number of tickers with a computable baseline, and the gaps;
   - each ticker's fair value against the current price; the twelve-month EPS, multiple and conditional target are reported separately;
   - the risk-free rate's source and observation date (receipt `rf_basis`); macro is quoted only as the frozen prior's environment band / strongest driver in one line, never as valuation scenarios;
   - 1/5/20-session short-horizon responses, their intervals and validation status; without samples write unknown;
   - changes against the previous independent report, computed only when the bases are comparable; company, rate, price, assumption and model changes are attributed separately and unidentified attribution is not invented;
   - the local path of the full report and the next data gaps.
   Numbers must come from the host receipt; the model's text cannot create prices. A 25 bp policy-rate cut, a 25 bp risk-free-curve shift and a 25 bp surprise are distinct inputs. The current short-horizon module does not cover the announcement-minute jump.
5. The daily frozen predictions live in this task's run archive and cannot be described as historically validated.

Artifacts of record are the capture, workflow, valuation, publication, report and job files under `var/valuation-daily/runs/<date>/<run-id>/`; `latest.json` points only to the most recent attempt, and a failure never falls back to an older successful price. Daily evidence and predictions are kept complete in the independent archive without rewriting old predictions.

Research judgements have zero authorization effect. Do not write trading state, zones, caps, broker orders or the intelligence workflow's files, and do not commit or push. Delivery happens inside the runner session; this task sends no Telegram or other external messages.
