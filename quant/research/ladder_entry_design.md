## 0. 这不是重开快车道（当天刚判否）

必须先说清楚，否则看起来像输了不认。

`fastlane_repair_gate_design.md` 当天的裁决是「不采纳幅度快车道，×2 确认保留」，
判据 1（风险调整后 ΔR）两个 k、主口径与 `_rescan`、T+20 与 T+60 全部不过。
**那条测的是「全额提前」**：FAST 全仓在 D1 之后进 vs SLOW 全仓等 ×2 之后进。

本轮问的是**另一个自由度**：**分档**。三点区别，每一点都独立于上一轮：

| | 快车道（已否） | 本轮 |
|---|---|---|
| 变的是什么 | **时点**（提前一天全额进） | **执行结构**（同一时点起分档进） |
| 对照 | FAST vs SLOW，单点 vs 单点 | 单点 vs ladder |
| 已知结果 | D1 全额 ≈ D2 全额（**平局**） | 未测 |

而且上一轮的结论正是本轮的**前提**：既然 D1 全额与 D2 全额是平局
（探路数字：R winsor A +0.227 vs B +0.242 @gate+1.0N/D1+60，跨 6 个参数格无方向），

**若本轮通过，两份文档都必须写明边界**：快车道否的是全额提前，本轮批的是分档提前；

（gate+1.0N 只有 5.2%，加地板读数完全不变）。**不是分母假象**；地板版更干净，取为主口径。

## 2. 假设

- **H-ladder**：在幅度达标的修复 gate 突破上，**分档入场**（首档买参与权 + 后档限价接回踩）
  相对**单点入场**同时降低混合入场风险与提高风险调整后收益
- **H0**：ladder 的优势来自**少部署**（不成交 = 不冒险 = R 好看），而非执行结构本身
  —— 判据 3（部署率地板）就是为杀这个而设

## 3. 设计

- **引擎**：复用 `gate_backtest2` 的 episode 构造（`klines_deep` 165 票，破位后收复）与
  滑点/止损扫描件；统计口径按月聚类 block bootstrap（同 round-2）
- **触发（运行前锁定）**：episode 内**首个**`close > gate` 的那一天记为 **D1**；
  要求 `close[D1] > gate + k·ATR20[D1]`，`k ∈ {0.5, 1.0}` 两格。gate = `cluster_gate`
  （incumbent；HVN 版  已判不采纳）
- **止损**：全臂 `stop = gate − 0.5×ATR20[D1]`（= live `bfloor_buf`），收盘 ×1 日触发，
  次日收盘出场，滑点 0.2%。**本轮不碰 stop 语义**（那要过 position-tiers 的回测闸门）
- **终点**：**D1+60 裁决**，D1+20 并列报告。终点自 **D1（决策点）**起算
  —— 从破位日起算会把「终点时还没入场」的 episode 混进来当 0 稀释全臂（探路阶段踩过）

### 臂（运行前锁定，不加第五条）

| 臂 | 定义 |
|---|---|
| **A**| D1 收盘全额入场 |
| **B1**| **现行的机械代理**：D2 收盘全额；且 `close[D2] > gate` 否则不入场（持现金） |
| **B2**| **更贴近 live 的代理**：D2 收盘确认后，在「D2 收盘价下方最近的 HVN 带」中点挂限价 |
| **C**| **ladder 50/30/20**：首档 D1 收盘；二三档限价 `max(close[D1] − {0.5,1.0}·N, gate)` |

- ladder 权重 **50/30/20 锁死**（house canon `entry_ladder_backtest`  定版，本轮不调）
- 限价挂单有效期 **10 个交易日**，未成交作废（该档资金留现金）
- **B2 的存在是有意的**：live 的入场不是"确认日市价买"，而是重画后挂 z1 限价。
  只拿 B1 当基线等于立稻草人 —— 这一点是 用户  当面指出的

## 4. 指标

- **混合入场风险 N**= `(加权平均入场价 − stop) / ATR20[D1]`（主诉求）
- **R**= `policy 收益 / 承担的风险比例`；重尾，**并列报 winsorized(5/95) 与中位**
  （快车道那轮实测 ΔR 均值 94% 来自 5 个 episode，均值单独不可信）
- **部署率**= Σ 已成交档权重（H0 的杀手）
- 并列（不参与裁决）：绝对收益均值/中位、止损率、各档成交率、p10

## 5. 判据（**运行前锁定**，按 k 分格独立执行，裁决终点 D1+60）

采纳 ladder 作为该场景的入场执行方式，当且仅当该 k 格**全部**成立：

1. **风险单位真的降了**：`风险N(C) − 风险N(B1)` 配对 CI90 **上界 < 0**
2. **R 真的更好**：`R(C) − R(B1)` 配对 CI90 **下界 > 0**，**且对 B2 同样成立**
   （两个基线都要赢；只赢稻草人不算）
3. **部署率 ≥ 80%**—— 防止靠不成交刷 R（H0）
4. **绝对 expectancy 不显著为负**：C 的收益均值 CI90 上界 > 0
5. **Kish ≥ 30**，否则报数据不足不裁决

任一不满足 → **不采纳，现行确认+单点入场保留**，否定结果写回本文档。
两个 k 都过 → **取更严的 k（更大者 = 更少触发）**；只有一个过 → 只在该 k 上采纳并写明边界。

### 10c. ⚠️ 必须写明的边界：增益不在你最关心的那一档

k=0.5 是 k=1.0 的**超集**，所以「k=0.5 采纳」= 对所有 >0.5N 的突破都用 ladder。
但把子集拆开看：

| 幅度带 | R(C) − R(B1) | 结论 |
|---|---|---|
| 0.5N – 1.0N（推出来的差） | 显著为正 | **增益全在这里**|
| **> 1.0N**| **−0.000，CI 含 0**| **平局**|

**立项时那四张卡（MRVL +1.22N / NVDA +0.95N / LITE +0.89N / MSFT +0.33N）全部落在
>1.0N 那一档**——也就是 ladder **对它们没有可测的增益**。

机制上说得通：幅度越大，价格离 gate 越远，ladder 的二三档要么挂在仍然很高的位置
（省不下多少），要么只有真正走坏的才回踩到（逆向选择）。**ladder 的价值在"刚过线的
普通突破"上，不在"跑得很凶的强突破"上。**

这与直觉相反，也与本项立项时的叙事相反——但它是预注册判据机械读出来的，照写。

### 10d. 风险单位这条链上它贡献了什么

| | 风险N | vs 现行代理 |
|---|---|---|
| B1（现行代理，k=0.5 池） | 1.46N | — |
| C ladder | **1.07N**| **−27%**|

**在 k=0.5 池上，ladder 单独把入场风险砍掉 27%**，而且是判据 ① 显著过关的。
剩余缺口交给 at-risk cap（`risk_unit_design.md` 的 (b)）。
注意在 >1.0N 那档 ladder 只砍 17%（1.85N→1.55N）且 R 不改善——**那一档的缺口
基本要全靠 cap**。
