# 修复 gate 的幅度条件快车道 — 预注册（起草，**运行前锁定**）

**状态**：✅ **已跑完并裁决→ 不采纳，×2 确认保留**。
两个 k、主口径与 `_rescan` 变体、T+20 与 T+60 —— **判据 1 全部不过**。完整结果见 §9。
**提出**：用户—— 「如果是强势突破 gate 并且突破幅度够大，是否可以不等 ×2、当天确认」。

## 0. 先说清楚：这**不是**重开 escape_velocity

`escape_velocity_redraw`（运行，verdict **C_keep_2day**）测过"提前一天"并否决了：
ΔT60 CI 含 0、止损率 **+9~13pp 显著恶化**。但它答不了本问题，有**两条结构性理由**，
且第一条是它自己写在设计稿里的：

1. **样本池不同（它自己声明过）**：原文——「`gate_backtest2` 的 `fire_scan need∈{1,2}` 测的是
   **修复路径 gate**（破位后收复）的确认日数；本回测测的是**上行逃逸**（箱体顶突破）——
   样本池方向相反，**结论互不覆盖**」。本问题问的正是**修复路径 gate**。
2. **止损模型把要测的机制消掉了**：escape_velocity 两个世界都用 `entry − 2×ATR20@入场`
   —— **入场锚定**，于是 FAST 与 SLOW 每股风险**按构造相同**。而 live 系统的 stop 是
   **gate 锚定**（`bfloor_buf`），入场越早离 stop 越近 → **每股风险越小**。
   那个设计恰恰抹掉了快车道在真实系统里唯一的收益来源。

3. **触发条件不同**：escape_velocity 的 FAST 资格是**量比 ≥2**（价格逃逸版只作敏感性报告、
   未参与裁决）。本问题的条件是**幅度**（离 gate 多远），从未被裁决过。

## 1. 立项证据（实测，7 张 live 卡）

风险放大**几乎全部发生在确认的第二天**：

| | gate | 确认 D1 收 | 确认 D2 收 | D2 跑掉 | 该卡实际承担 | 若 D1 入场 |
|---|---|---|---|---|---|---|
| **MRVL**| 189 | 193.78 | 218.59 | **+1.22N**| 1.67N | **0.70N**|
| **NVDA**| 204 | 211.88 | 219.22 | +0.95N | 1.64N | — |
| **LITE**| 716 | 779.89 | 849.47 | +0.89N | 1.17N | — |
| MSFT | 473 | 487.65 | 492.81 | +0.33N | 1.59N | — |
| INTC / MU / AAOI | — | — | — | ~0.0N | 0.5-0.7N | — |

放大的四张与第二天跑掉的四张**是同一组**。这不是巧合，是机制：
**×2 确认要求本身就是入场远离 stop 的成因。**

## 2. 假设

- **H-fast**：修复 gate 上，`close > gate + k×ATR` 的**幅度确认**替代第二日的**时间确认**，
  在 **gate 锚定止损**下风险调整后更优（每股风险显著更小，抵消更高的止损率）
- **H-slow**：幅度不能替代时间；止损率恶化吞掉风险单位的改善（escape_velocity 在箱体顶
  场景已成立，本回测检验它是否也适用于修复路径 + gate 锚定止损）

## 3. 设计

- **引擎**：复用 `gate_backtest2` 的 episode 构造与统计口径（修复路径 episode 本就是它的样本）
- **样本**：`klines_deep` 165 票；episode = round-2 同定义（破位后收复）
- **FAST 资格（运行前锁定）**：确认首日 `close[i] > gate + k×ATR20[i]`，`k ∈ {1.0, 1.5}` 两格
- **两世界（共同起点、共同终点 T+20/T+60、1 元本金）**：
  - **FAST**：资格成立 → `i+1` 收盘买入（含 1 日执行延迟，同 escape_velocity 惯例）
  - **SLOW（现行）**：需 `close > gate` 连续 2 日 → `i+2` 收盘买入；`i+1` 跌回 gate 下 → 不入场持现金（ITT）
- **⚠️ 止损（本回测的关键差异）**：两世界**都用 gate 锚定**`stop = gate − 0.5×ATR20@确认日`
  = live 的 `bfloor_buf`，收盘 ×1 日。**不用入场锚定的对称 2N**—— 那正是 escape_velocity
  看不见本机制的原因
- **cooldown / 右截断 / SLIP 0.2%**：同 round-2

## 4. 主指标：**风险调整后**，不是绝对收益

这是与 escape_velocity 最大的口径差异，运行前锁定：

- **主口径 `R-multiple`**：`(终点收益) / (入场价 − stop)` —— 即"赚了几个自己承担的风险单位"。
  快车道的立论就是**分母更小**，只看分子会系统性低估它
- 并列报告（不参与裁决）：绝对 expectancy ΔT20/ΔT60、止损率差、p10 差、每股风险 N 值分布

## 5. 判据（**运行前锁定**）

按 `k` × regime 分格独立执行。采纳幅度快车道，当且仅当该格：

1. **R-multiple 期望差（FAST−SLOW）CI90 下界 > 0**（风险调整后真的更好）
2. **止损率差 CI90 上界 < +8pp**（比 escape_velocity 的 +5pp 放宽 3pp —— 因为本设计里
   FAST 每股风险更小，同样的止损率代表更小的美元损失；**放宽幅度预注册于此，不许事后调**）
3. **绝对 expectancy 不显著为负**（CI90 上界 > 0）—— 防"风险调整好看但实际亏钱"
4. 该格 **Kish ≥ 30**，否则报数据不足不裁决

任一不满足 → **不采纳，×2 确认保留**，否定结果写回本文档 + `zone-maintenance.md`。
两个 `k` 都过 → 取**更严的**k（更少触发 = 更保守）。

## 5b. 运行前补记（，**跑之前**写下）

原稿有四处不指定就等于"跑完再挑"的地方。在动代码之前锁死：

| # | 原稿没说的 | 锁定 | 为什么这样锁 |
|---|---|---|---|
| **A**| FAST 幅度不达标那天怎么办 | **decision arm = `fast_hybrid`**：达标→次日收盘进；不达标→**回落 ×2 日原规则**| 用户的问句是「够大就**不等**×2」——×2 仍在，只是被跳过。纯 FAST（不达标就弃）会让两臂在**参与率**上也不同，测出来的就不只是 timing 了。`fast_pure` 仍跑，作机制拆解 |
| **B**| gate 用哪种画法 | **`cluster` 单一**（incumbent；round-2 里唯一有拒绝权的画法，且 8/7 HVN 已判不采纳） | §7「不调 k 之外的自由度」 |
| **C**| 裁决终点 | **T+60**，T+20 并列报告 | 与 round-2 / 其余预注册同拍 |
| **D**| 「k × regime 分格」的 regime | **裁决单元 = k（合池）**；引擎已有的 5 个 era cohort 并列报，受 Kish≥30 守卫 | §5 末句「两个 k 都过 → 取更严的 k」本身就把裁决单元定在 k 上。2 k × 5 era 全过=保守方向的多重比较陷阱。**但若某 k 合池过、却在 ≥3/5 个 era 上符号翻转 → 明写出来，不静默采纳**|

**样本条件（同样运行前锁定）**：只计**窗口内出现过首个 `close > gate` 的 episode**。
没有 gate、或整个窗口从未收上去的 episode 对本问题（"确认之后要不要等第二天"）无信息，
两臂都是现金、配对差恒为 0 —— 计进去只会稀释效应量并虚报 n。Kish 按此条件后的样本算。

**SLOW 的失败分支按原稿字面实现**（首个确认日之后次日跌回 gate 下 → 不入场持现金，
不再等下一次）。⚠️ 这条对结果可能敏感，所以**并列跑 `_rescan` 变体**（失败后继续扫下一次
确认机会，= round-2 `fire_scan` 的语义）：两者若给出相反结论，说明结果是"放弃规则"的产物
而不是幅度本身的，必须写出来。

**R-multiple 的未入场取值 = 0**（没冒风险也没收益），与 policy/ITT 口径一致。

## 6. 已知混淆

| 混淆 | 处理 |
|---|---|
| 幅度与动量共线（跑得远的本来就强） | 这正是要测的东西, 不是要控制的东西；但**并列报"无幅度"对照池**，验证幅度本身有判别力 |
| gate 锚定 stop 让 FAST 天然风险小 → R-multiple 有利 | **这是机制不是偏差**；判据 3（绝对 expectancy 不负）防它变成"用更小的仓赌更差的赔率" |
| 存续票池 | 同 round-2/escape_velocity，偏向高估突破跟随 → 若 FAST 仍不过，结论更稳 |
| 与 escape_velocity 结论表面冲突 | 两者样本池与止损模型都不同；**若本回测通过，须在两处文档写明适用边界**：修复 gate 用幅度快车道、箱体顶突破维持 ×2 |

## 9. 结果与裁决（，`quant/research/fastlane_backtest.py`）

样本 4,390 episodes（窗口内出现过首个 `close > gate`）/ Kish ≈195.1 / gate = cluster /
两世界均 gate 锚定止损。裁决终点 T+60。

### 9a. 判据读数：判据 1 全部不过

| 变体 | k | 达标率 | ΔR (fast−slow) | CI90 | 判据1 | 判据2 | 判据3 | 判据4 | 结果 |
|---|---|---|---|---|---|---|---|---|---|
| 主口径 | 1.0 | 11.3% | +0.068 | **[−0.004, +0.159]**| ✗ | ✓ | ✓ | ✓ | FAIL |
| 主口径 | 1.5 | 3.5% | +0.038 | **[−0.009, +0.119]**| ✗ | ✓ | ✓ | ✓ | FAIL |
| _rescan | 1.0 | 15.0% | +0.056 | [−0.018, +0.151] | ✗ | ✓ | ✓ | ✓ | FAIL |
| _rescan | 1.5 | 4.7% | +0.038 | [−0.012, +0.122] | ✗ | ✓ | ✓ | ✓ | FAIL |

T+20 同向不过（k=1.0 CI90 [−0.013, +0.129]；k=1.5 [−0.016, +0.119]）。
主口径与 `_rescan` **结论一致**→ 结果不是"放弃规则"的产物（§5b 那条守卫过了）。

方向是**正的但不显著**：这是"没证明有用"，不是"证明有害"。

### 9b. 为什么——立论的机制在数据上几乎不存在

设计稿的立论：`×2 确认要求本身就是入场远离 stop 的成因`。在**达标子集**上直接量它：

| k=1.0，达标子集 n=497 | FAST | SLOW | 差 |
|---|---|---|---|
| 每股风险中位 | **1.821N**| **1.943N**| **仅 0.12N**|
| 止损率 | 52% | 47% | +5pp |
| ΔR 均值 / 中位 | — | — | **+0.602 / +0.002**|

**⚠️ 最极端 5 例（共 497）贡献了 ΔR 总量的 94%。中位数是 +0.002 ≈ 0。**
所谓的风险调整优势不是一个系统性效应，是几笔尾部。

**幅度条件是自我拆台的**：`close > gate + k×ATR` 只在价格**已经跑远**时才成立
（达标子集里 FAST 自己的入场就已经离 stop 1.82N）。所以它按构造无法交付
"入场离 stop 更近"这件事——而那正是它唯一的收益来源。

### 9c. 无幅度对照池说清了真正的因

§6 要求的对照臂 `fast_nomag`（收上 gate 就次日进，**不看幅度**）：

| | 每股风险中位 | 止损率 | R 中位 |
|---|---|---|---|
| slow（×2） | 1.36N | 44% | 0.000 |
| **fast_nomag（×1，无幅度）**| **1.04N**| **68%**| **−0.739**|

**早进确实能把每股风险从 1.36N 压到 1.04N —— 但止损率同时 +24pp。**
所以风险单位的改善是真的，只是被 whipsaw 全额吃掉，和 round-2b 关于
「stop 贴着 gate = whipsaw 机器」的实测同源。

合起来：**能减小风险单位的做法（不看幅度早进）会被打脸；不会被打脸的做法
（看幅度）减不了风险单位。**幅度快车道落在这两难的错误一侧。

### 9d. 那 §1 那七张 live 卡怎么解释

它们是**当前在场的书**——即那批"第二天确实跑掉了"的设置。全样本说 D2 平均只多跑
0.12N，而那七张里有四张跑了 0.9–1.2N。**7 张卡看到的是选择，不是规律。**
这正是预注册存在的理由：立项证据来自 live 观察，裁决必须来自全样本。

### 9e. 与 escape_velocity 的关系

不冲突，反而**同向加强**：escape_velocity 在箱体顶用入场锚定止损否决了提前一天；
本回测在修复 gate 用 gate 锚定止损、并把主口径换成风险调整后的 R——
**换了样本池、换了止损模型、换了主指标，结论仍然是"提前一天不划算"。**
`×2 确认` 在两个场景下都保留。

  gate 锚定 stop / R 定义 / 裁决四分支）
- 报告存档 `tmp/backtest/fastlane_report.md`
- **不动 live**：`bfloor_buf`、ladder、确认口径一行未改

## 8. 与另两个立项的关系

本项与 `risk_unit_design.md` 是**同一问题的两条解法**，可以叠加但**必须分别裁决**：
快车道从**源头**减少入场与 stop 的距离；at-risk 天花板在**结果端**限制风险。
若快车道通过，at-risk cap 的必要性会下降（但不消失——它还管别的来源）。

## 10. 边界补记（，`ladder_entry` 裁决之后）

同日晚些时候 `ladder_entry_design.md` **采纳**了「D1 幅度达标 → 当日转移 + 分档入场」，
已接线进 live。这**不是**本轮裁决的翻案，两者管的是不同自由度：

| | 本轮（已否） | ladder（已采纳） |
|---|---|---|
| 变的是 | **时点**：提前一天**全额**进 | **执行结构**：同一时点起**分档**进 |
| 结果 | ΔR 判据全格不过（D1 全额 ≈ D2 全额，平局） | 风险 N 1.46→1.07（−27%），R 对两个基线都显著更好 |

**本轮的平局结论正是 ladder 立项的前提**：既然 D1 全额与 D2 全额没有差别，
「等不等第二天」就没有答案可给——真正没被问过的是「**怎么进**」。

live 现状：`regime_transition.PARAMS["fastlane_k"] = 0.5` 只授权**转移与画 zone**，
入场执行由 `entry_guard` 的 `repair_reclaim` 三档 ladder 承担。
**「D1 收盘全额买入」这条路径至今没有任何证据支持，不要因为快车道接线了就默认它可以。**
