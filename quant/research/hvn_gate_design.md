# HVN 锚定 gate vs pivot 簇 gate — 预注册（起草，**运行前锁定**）

**状态**：✅ **已跑完并裁决→ 不采纳，cluster 保持 incumbent**。
判据全过但**拒绝权无差异 = 平手**，走预注册 §3 末句。完整结果见 §9。

## 0. 为什么现在才可能问这个问题

round-2（`gate_backtest2`，165 票 / 4,670 episodes / Kish≈194）的核心裁决是：

> 12 主格 expectancy **全部显著负**（gate 是保险不是 alpha，保费 ≈1pp/episode），
> **但 cluster gate 首次给出拒绝权**—— 被拒 episode 的反事实差 **-9~-14pp（显著）**。
> 原文结论：「**画线维度的判别力真实存在**，确认维度（days/vol）只是在放行样本上加迟到成本」。

也就是说：**gate 值不值得，取决于线画在哪里，而不是确认几天。**而 round-2 里
「画线维度」只测了三种画法：`swing`（确认摆动高点）、`ma60`、`cluster`（pivot 聚类）。
**三种全部只用价格，没有一种用成交量。**

 之前我们没有可信的 volume-at-price（旧算法把每根日线压成一个点，对真值
TVD 21.5%、POC 只对 7/10）。修好之后（TVD 7.2%、POC 10/10），**HVN 锚定的 gate 第一次
成为可测的候选**—— 而且它落在 round-2 已证明有判别力的那根轴上。

## 1. 假设

**H1**：`gate = 价格上方最近 HVN 带的上沿` 在**拒绝权**上不弱于 `cluster`（pivot 簇）。

直觉（运行前记录，防事后编故事）：pivot 簇记录的是**价格到过哪里**，HVN 记录的是
**筹码堆在哪里**。反弹被打回的地方常常是套牢盘出货的地方 —— 后者可能是更直接的因。
但也可能相反：HVN 是"成交多"不是"卖压大"，而 gate 要的是后者（同
「真空 ≠ 无阻力」那条教训的镜像）。**两个方向都合理，所以要测。**

## 2. 设计（复用已审查引擎）

- **引擎**：`gate_backtest2` 的 episode 构造 / 反事实 / 统计口径**原样复用**（同层 import，
  round-2 已审查）。只新增一种 gate kind。
- **Gate 格**：`kinds{swing, ma60, cluster, **hvn**} × days{1,2} × vol{off,on}`，
  `hvn` 之外三格是**回归对照**（必须复现 round-2 数字，不复现就说明环境有问题、中止）。
- **hvn gate 定义（运行前锁定，不许跑完再调）**：
  - profile = `core/technical.volume_profile`（三角铺开）over 破位日 i 往前 **60 根日线**
  - bucket = `core/technical.auto_bucket(close_i, ATR14_i)`
  - HVN = `level_map.top_hvn(profile, n=5)` 产出的带
  - gate = **价格上方最近那条 HVN 带的上沿**；无则回退 `cluster` 的取法（与 round-2
    的 structure 回退同构，并记录回退比例）
  - **破位日画一次，固定**（卡片语义：gate 画卡时定），与 cluster 同拍、无前视
- **数据**：`market/klines_deep/`（165 票，带 turnover）。⚠️ **只有日线**——
  profile 用三角铺开近似（TVD ~7%），**不是 60m 真值**。两臂同法，做 gate 种类之间的
  **相对**比较有效；**结论不得声称是真值口径**。

## 3. 判据（**运行前锁定**）

采纳 `hvn` 作为画卡方法，当且仅当：

1. **拒绝权不弱**：`hvn` 的被拒 episode 反事实差 ≤ `cluster` 的（即至少一样能挡住坏的），
   且其 CI90 **排除 0**
2. **保费不更贵**：`hvn` 的 expectancy 不比 `cluster` 差超过 **0.5pp/episode**
   （gate 本来就全负，这里只要求不显著更负）
3. **触发率不退化**：`hvn` 的触发率落在 `cluster` 的 ±15pp 内
   —— round-1 的教训是「**总会触发的闸门是延迟器不是闸门**」，反过来也成立：
   几乎不触发的 gate 等于禁入
4. **回退比例 ≤ 20%**（上方无 HVN 而回退 cluster 的样本占比。超过说明这个定义在多数
   情形下根本不适用，那它就不是一个方法）

任一不满足 → **不采纳，cluster 保持 incumbent**，把否定结果写进本文档。
平手（判据全过但差异不显著）→ **保留 cluster**（语义更简单，且已在 live 用了三个月）。

### 3a. 裁决格（**运行前补记，**）

原文没说四个 gate 格（days{1,2} × vol{off,on}）里哪个裁决 —— 不指定就等于跑完挑一个，
所以在**跑之前**锁死：

- **裁决格 = `_x2`（×2 日确认 / vol off / primary 止损 / T+60）**
  - `×2`：与 live 修复 gate 的确认口径一致
  - `vol off`：`gate_backtest2.vol_ok` 是**相对量比裁决之前**的绝对量比（20 日 SMA ≥1.2），
    而 live 的量腿  已换成 `RelVR`（个股量比/基准量比）。用一个**已不代表 live**
    的量腿去比较**画线维度**，只会往主判据里掺进不相干的噪音
- 另外 3 对（`_x1` / `_x1_vol` / `_x2_vol`）**全部报出来**作稳健性；**若它们与裁决格结论相反，
  照实写，不改裁决**
- 对照口径：hvn 与 cluster 取**同格**比较（paired，同 episodes 同止损）

## 3b. 早停筛查结果（运行，主回测**之前**）

预注册要求「预先报两者重合率，>70% 则本假设几乎无信息、直接停」。
`quant/research/hvn_gate_screen.py` 全池跑完：

| | 结果 | 门槛 |
|---|---|---|
| episodes | **4,677**（round-2 是 4,670 → episode 构造忠实复现） | — |
| **重合率**（gate 差 < 1 bucket） | **20.7%**| >70% 停 → **PROCEED**|
| HVN 无定义（回退 cluster） | **3.8%**| ≤20% ✓（判据 4 已过） |
| gate 差异中位 / p90 | 0.61N / 2.27N | — |
| **HVN 高于 cluster 的比例**| **84.2%**| — |

⚠️ **运行前预测（记在这里防事后合理化）**：HVN gate 系统性地比 pivot 簇**高约 0.6N**
（84.2% 的样本在其上方）。机制上说得通——pivot 簇是**被拒的点**，HVN 是**筹码堆积处**，
破位后头顶的成交货架通常落在最近拒绝点之上。

**这直接指向它最可能的死因：判据 3（触发率须落在 cluster 的 ±15pp 内）。**
更高的线 = 更难够到 = 触发率下降。若主回测显示触发率掉出 ±15pp，那不是意外，
**是本筛查已经预告过的结果**；届时按预注册判死，不许改判据救它。

反过来，若触发率仍在带内而拒绝权更强，那才是真发现：说明"筹码在哪"比"被拒在哪"
是更直接的因。

### 3c. gate 落点诊断（主回测前，只看落点不看收益）

顺带查了一个退化风险：**破位日自己那根 bar 也在 profile 窗口内**，若当日放量，
它的桶可能挤进 top-5，gate 就贴在现价上方 = 形同虚设。全池实测 (n=4,497)：

| gate 高于破位收盘 | p5 | p10 | p25 | **p50**| p75 | p90 |
|---|---|---|---|---|---|---|
| | 0.29N | 0.43N | 0.68N | **0.90N**| 1.07N | 1.85N |

「贴脸 gate」(<0.2N) 仅 **2.6%**，<0.5N 为 13.2%。**定义没有退化，不修改**
（合成 fixture 里出现是因为只有两个价格簇；真实数据的桶足够多）。
诊断只看 gate 落点、**未触碰任何前向收益**，不污染主回测。

**测试锁**：`tests/research/test_hvn_gate_screen.py` 把上述定义（60 根窗口 /
top-5 / 取上沿 / 用共享 `volume_profile`）逐条钉死 —— 预注册说"运行前锁定不许改"，
测试就是那句话的强制点，主回测跑起来后任何改动都会变红。

### 9b. 四判据：全过

HVN 回退 cluster 比例 **3.9%**（判据 4 上限 20% ✓）。primary × T+60：

| cell | 触发率 | ΔT60 | CI90 | p10 | 止损率 | nf 反事实 |
|---|---|---|---|---|---|---|

### 9c. 但配对 h2h 说明它是平手 —— 判据全过 ≠ 采纳

四判据只给各自的 CI，不给**差的 CI**。H1 写的是"**不弱于**"，是非劣性假设；
非劣通过之后还得问"有没有更好"。补跑同 episodes 的配对 block bootstrap：

| cell | Δ拒绝权 gap | CI90 | Δexp | CI90 | Δ止损率 | Δ触发率 |
|---|---|---|---|---|---|---|
| _x1 | −0.1% | [−0.8,+0.5] | −0.4% | [−0.6,−0.1] | −6.8pp | −5.4pp |
| _x1_vol | −0.1% | [−0.7,+0.4] | −0.4% | [−0.6,−0.1] | −6.2pp | −5.4pp |
| **_x2 ★**| **−0.2%**| **[−0.8,+0.3]**| **−0.2%**| **[−0.5,−0.0]**| −6.9pp | −5.6pp |
| _x2_vol | −0.4% | [−0.8,+0.1] | −0.3% | [−0.5,−0.1] | −5.0pp | −5.4pp |

- **拒绝权差 CI90 四格全部含 0**—— H1 那根轴上，HVN 与 pivot 簇**没有区别**
- **expectancy 差 CI90 四格全部排除 0 且为负**—— HVN 的保费**显著更贵**
  （只是没贵过判据 2 的 0.5pp 容差，所以判据仍然"过"）

**→ 预注册 §3 末句：平手 → 保留 cluster。裁决 = 不采纳。**

### 9d. 它到底是什么（机制，非事后编故事）

早停筛查运行前就预测了：HVN 系统性地比 pivot 簇**高约 0.6N**（84.2% 的样本在其上方）。
主回测把这个预测的后果原样兑现——触发率 −5.6pp、止损率 −6.9pp、p10 +0.9pp、
expectancy −0.2pp：**这是"把线画高一档"的全套签名，不是"画得更准"的签名。**
更高的线买到更多保险、付更贵保费，而**判别力一点没变**。

这反过来给 round-2 的结论加了一个限定：round-2 说"画线维度的判别力真实存在"
（cluster 的拒绝权 −9~−14pp 显著，而 swing/ma60 触发率 98-100% 基本无拒绝权）。
本次证明那份判别力**对具体画法不敏感**—— 换一种完全不同的证据（筹码分布 vs 被拒点）
重画，拒绝权分毫不差。所以真正起作用的是"**头顶有没有一条供给线**"这件事本身，
而不是"用哪种方法找到它"。

设计稿 §1 预留的失败方向（"HVN 是成交多不是卖压大"）**部分成立**：它没有更差，
但也没有更直接——两者在拒绝权上是同一个东西的两种测量。
